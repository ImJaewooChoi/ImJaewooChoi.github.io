Auto‑labeling pipeline

Daedong AILab, Senior AI Researcher, May 2024–Present.

Problem

Segmentation data and region‑grounded vision‑language data were labeled by hand.

My role

Besides building the video auto‑labeling pipeline, I set the label taxonomy and the annotation guidelines and compiled the COCO‑format training datasets.

Method

  1. Point prompts and mask corrections were turned into tracked masks with consistent IDs across frames.
  2. Image and video inputs share TensorRT engines, so the same computation is not run twice.
  3. Qwen‑series vision‑language models wrote the region‑grounded object descriptions and checked them. I sent uncertain cases to a second review and linked the verified descriptions to the instance annotations.

Model: a tracker built on SAM3

The labeling tracker is based on the SAM3 video tracker, compiled to TensorRT engines and driven by clicks and seed masks. Class names and track IDs come from the labeling backend, so the model only has to produce masks. The engines follow an open‑source TensorRT build of that tracker. It keeps SAM3's weights and changes how the work is divided between engines and where memory lives on the GPU.

Model structure

The tracker runs as separate engines. A ViT image encoder runs once per frame, and a neck turns its output into multi‑scale features. Two prompt paths can start an object. The point‑prompt decoder predicts a mask from the first positive or negative click and refines it with each later click. The mask‑prompt init takes a seed mask and writes it into the memory bank. On every later frame, a step engine runs memory attention over that bank of past mask memories and object pointers, predicts the object's mask and encodes the new memory. Each path returns mask logits with an IoU estimate and an object score.

What the TensorRT build changes

Splitting the graph lets the costly part run once. The encoder's output buffer is bound directly as the neck's input, and the neck's three feature maps feed the init and step engines without any copy. A frame with many objects still pays for one encoder pass.

The step engine takes memory as a gathered list of key tokens with a valid‑key count per object, not as a fixed stack of frames. Each key carries its own rotary position index and keeps its place in the frame when other keys are dropped. Object pointers sit before the memory keys, so the count mask never cuts a pointer in a mixed batch. With the full memory, the computation matches the original tracker. The difference is per‑object key pruning: only keys near the object's last mask survive, plus a coarse background grid for global context. Attention cost follows the number of keys, so each object pays only for the keys around it.

Memory stays on the GPU as FP16 token rows in a reusable buffer pool. Before each step, the CPU writes a short table of row addresses and a small CUDA kernel gathers those rows into the step's input. Only address tables, key counts, scores and low‑resolution mask logits cross the bus. History is bounded, with a few conditioning memories, a recent window and a capped pointer list per object. Several objects advance in one batched step, and the first layer's self‑attention over the frame is computed once for all of them. The neck, init and step engines run in FP16, while the point‑prompt decoders and, in this pipeline's mode, the encoder layers stay in FP32.

How the pipeline uses it

On top of SAM3, I built the prompting, serving and post‑processing layer.

  1. Clicks on a video frame accumulate. Each new click refines the previous mask on the GPU, and the object's memory is committed only after the last click, so a half‑finished mask never reaches the memory bank.
  2. For single images, point heads are cut out of the video point‑prompt graphs. They keep the mask, IoU and object‑score outputs and drop the memory outputs.
  3. Image and video requests share one image encoder and neck. Every engine is loaded once per process and shared by concurrent workers.
  4. Token pruning for memory and query tokens is reimplemented. Parity tests confirm it picks the same tokens as the original selection.
  5. A preview session snapshots its image features on the GPU. Later clicks on the same image restore that snapshot and skip the encoder.
  6. GPU inference and CPU post‑processing run as separate services. The GPU side returns raw mask logits; the CPU side fills holes, resizes the masks and writes COCO polygons or RLE masks.
  7. A correction at a later frame enters as new clicks or a seed mask at that frame. The object keeps its track ID from there on.

Captioning after labeling

After auto‑labeling finished, Qwen‑series vision‑language models captioned the labeled data in three stages:

  • Each mask got a description of the object it covers.
  • Each mask also got a caption of its relationship to the image.
  • The whole image got a caption of its own.

The verified captions were linked to the instance annotations.

Result

Labeling one image cost about USD 1.05 before this pipeline and about USD 0.036 after it, a 96.6% reduction.
